# Glossary

Shared vocabulary for the Studio's UI parts and code concepts, so people and agents use the same
words. Add new terms here, alphabetical, one line each; keep code names in backticks. Terms marked
"(planned)" do not exist in the code yet; drop the marker when one is built.

- **Agents window**: the VS Code companion window for agent sessions; it mounts the working folder of the active session as the workspace folder (`updateWorkspaceFolders`) and replaces or removes it on each session switch. Studio declares its support (`capabilities.agentsWindow` in `package.json`); a folder change promotes or demotes previews (`onFoldersChanged` in `src/session/hostEvents.ts`).
- **Alert**: GitHub `> [!TYPE]` callout; inserted by the Alert button of the GFM group, whose type list opens at the caret (`popoverAtCaret` in `src/page/modules/editActions.ts`).
- **Anchor icon**: marker rendered for a MyST `(label)=` target (`span.okf-anchor`, tooltip "Anchor: name"; first child of the next paragraph or heading, else in a `div.okf-anchor-row`).
- **Anchor button**: toolbar toggle that ties preview scrolling to the editor (`data-sphinx-preview-anchor`).
- **Area**: a feature category of the extension (one of the 16 groups of `test/shared/e2eGroups.ts`, an okfreq scope); "feature category" is the wording of share cards.
- **Block editor**: raw Markdown text box that replaces a mapped block in edit mode (`.sphinx-preview-block-editor`, `openBlockEditor` in `src/page/features/blockEditor.ts`).
- **Blank-line block**: block shown in edit mode for one shown blank line (`.sphinx-preview-blank-lines`, `installBlankLines` in `src/page/features/blankLines.ts`); reachable by arrows, Enter or a click, it opens an insertion editor that writes in place of that one line, and is removed with Delete (that one line) or its Delete block button. Inside a container (a list item, a quote, an alert, an admonition, a context-tag panel, a figure, a card, a grid item, a definition, a footnote) it shows in the container that holds the run, and a block typed in it takes that container's indent; a run inside a grid, a closed `details`, a fold or an included file shows none. It never carries `data-sphinx-source-line`.
- **Quote run**: two or more consecutive empty quote lines (`>` and nothing else) of the same depth and marker columns, inside a quote, an alert, an admonition, a definition or a footnote (`quoteBlankRuns` in `src/core/mapping/blankRuns.ts`); it is a blank run, listed with the plain runs.
- **Empty quote line**: a line of quote markers and nothing after the last one (`emptyQuoteLine` in `src/core/mapping/quoteLine.ts`); a quote run is made of them.
- **Container indent**: the text a block written in a blank run takes after its quote part to stay in the container that holds the run (`blankRunIndent` in `src/core/mapping/blankRunContainer.ts`): the item's content column, a directive's fence indent, a definition's or a footnote's inner indent.
- **Shown blank line**: a blank line that gets a blank-line block: of N blank lines between two blocks the last N-1; every line at the end of the body, at line 1 of a file without frontmatter and in a body of only blank lines; all but the first empty quote line of a quote run.
- **Separator**: the blank line (or first empty quote line) between two blocks, which stays hidden in edit mode.
- **Blank run**: two or more blank lines (spaces and tabs only) between top-level blocks, between two items of a list or inside a list item, at the start or at the end of the body (`blankRuns` in `src/core/mapping/blankRuns.ts`), or a quote run inside a container; the host lists the shown lines of them, single ones included, in a hidden `data-okf-blank-runs` element.
- **Block move**: swap of a top-level block with its neighbour from the insert point arrows (`planBlockMove` in `src/core/mapping/blockMove.ts`, `SourceEditController` in `src/session/features/sourceEdits.ts`).
- **Blur commit suspension**: while a host round trip marked `dialog` is pending (`hostRequests.ask(…, { dialog: true }, …)` in `src/page/modules/hostRequests.ts`: the `{doc}` and image file pickers), the text box blur and the palette `onLeave` do not save, so the block editor stays open under the native dialog; `cancelAll()` in `closeBlockEdit` and the request timeout clear it.
- **Block selection**: contiguous run of top-level body blocks selected in edit mode with Shift+click or Shift+Up/Down (`data-sphinx-preview-block-selected`, model in `src/page/modules/blockSelection.ts`); Delete or Backspace deletes it.
- **Content indent**: the spaces that bring a line to the content column of a list item (CommonMark: the marker, then 1 to 4 columns; a tab runs to the next stop of 4); a block typed in a blank run inside an item takes it (`listItemIndent` in `src/core/mapping/listItemIndent.ts`).
- **Delete block button**: the `×` button of an insert point bar, right after the down arrow (`createDeleteBlockButton` in `src/page/modules/deleteBlockButton.ts`); it deletes the block, or the block selection ending at it, in one undo step; none for an included block.
- **Feature introduction**: the one-time notice that tells a reader about a new capability (none today), shown once per feature and again on `showFeatureIntroductionsAgain` (`src/session/featureIntroductions.ts`).
- **Full ID**: `StRS-MDOKFSTUDIO-BLOCK-003`, the ID a requirement is named by everywhere on the requirements viewer: eyebrow, tab and share titles, breadcrumb, pager, lists and captions.
- **Jump**: a selection change of kind Command with one selection in a Markdown text editor, or on a side of a text diff whose real file is Markdown (a search result, Quick Open `file.md:40`, Go to Line, a link, Problems); the host tells it from a cursor move in `src/core/navigation/jumpSignal.ts` and `src/host-vscode/editorJumps.ts`, and the side preview marker reads it.
- **Line marker**: the arrow in the margin of the preview that marks the line a jump asked for; it stays through scrolls and layout changes and goes on a pointer press, an edit or a new line, and sits on the table row, the exact line of a hidden tab (shown first) or the front matter property row of the line (`src/page/features/lineMarker.ts`, `lineMarkerPlacement.ts`); the side preview that follows the editor shows it on a jump too, and it goes there on an edit of the document from the text editor or a switch of file.
- **Marker line**: a source line the renderer writes on an element for the line marker only (`data-okf-marker-line`, `data-okf-marker-end-line`): a table row, or a block inside a tab item; it is never a mapped block and never a click target, and the front matter section carries `data-okf-frontmatter-end-line` (`src/page/features/lineMarkerPlacement.ts`).
- **Raw copy**: the copy of a native text selection of the page as the raw Markdown under it (text/plain), with the rendered selection as text/html (`src/page/features/rawCopy.ts`, `src/core/mapping/rawCopy.ts`); not the block selection's copy, nor the code block's Copy button.
- **Edge balancing**: with `preview.rawCopy.balanceEdges` on, the raw copy adds the opening or closing delimiters and lines of the constructs that enclose only one edge of the selection (`src/core/mapping/rawCopyBalance.ts`); a node encloses an offset when `start < offset < end`.
- **Selected cell**: table cell the keyboard moved to with Right from a selected table and the arrows after it (`data-sphinx-preview-cell-focus`, model in `src/page/modules/structuralCursor.ts`, view in `src/page/features/structuralNavigationView.ts`); Escape goes back to the table block and Enter opens its cell editor.
- **Chip**: small inline marker in the preview, gray for an HTML comment and green for TODO (`.okf-chip`, `src/core/render/commentMarkers.ts`).
- **Comment thread**: review discussion attached to quoted text, stored in a sidecar file (`src/core/comments/commentModel.ts`, `src/page/modules/commentThreads.ts`).
- **Companion marker file**: a tracked file under `src/` or `test/` named `*.markers.ts` or holding a `// Companion of: <path>` line; it holds the requirement markers that cannot live in the file they belong to (the host), only comment lines and `export {};`, each marker line naming its scenario or code point after an em dash (`just check-markers`, `scripts/check-marker-companions.mjs`).
- **Content patch**: in-place replacement of the content container `#sphinx-myst-preview-content` instead of a full page reload (`src/core/preview/contentPatch.ts`).
- **Copy button**: floating button over a hovered code block that copies its raw code (`data-sphinx-preview-code-copy`, `src/page/modules/codeCopy.ts`).
- **Diff editor**: the VS Code editor that shows two versions of a text side by side or inline (a git diff, a file compare, the search and replace preview); its tab input is a `TabInputTextDiff`. Studio's side preview works next to it (`src/host-vscode/diffRealFile.ts`).
- **Real file (of a diff)**: the side of a diff editor that is a saved `.md` file of the `file:` scheme (the active side when both are, else the only one), or, for a diff with no such side, the working-tree file at its path (a stand-in, never scroll-synced); it is the file the side preview shows (`realFileOfDiff`).
- **Document store**: the port that holds the documents a host shows: their text, revision and line breaks, and the edits applied to them (`DocumentStore` in `src/host-api/documentStore.ts`); the VS Code host wraps `TextDocument`, `src/host-memory/` keeps them in memory.
- **Edit action**: one registered editing operation (`src/page/modules/editActions.ts`) used by shortcuts and the palette.
- **Edit lock**: host-side record that an inline edit is open, deferring work that would replace the page (`src/core/state/editLock.ts`).
- **Edit mode**: toolbar toggle that makes preview blocks editable (`data-sphinx-preview-edit-toggle`).
- **Edition palette**: bar of edit actions above an open block editor (`src/page/modules/editPalette.ts`, `.sphinx-preview-edit-palette`).
- **Figure editor**: form for `{figure}` options above the block text box (`src/page/modules/figureDirective.ts`, `src/page/modules/figurePanel.ts`).
- **Fresh workspace**: a workspace that has stored no theme mode, toolbar state or palette mode; it starts with the built-in defaults (`DEFAULT_PREVIEW_THEME_MODE` cream, `DEFAULT_VIEW_PREFERENCES.toolbarCollapsed`, `editing.defaultPaletteMode` gfm). A stored choice always wins. The visual mock host pins `PINNED_WORKSPACE_CHOICES` (`test/visual/renderOptions.ts`) except for `freshWorkspace` pages.
- **First-element gap**: fixed 40 px space above the first rendered element; `--sphinx-preview-first-clearance` (`src/page/modules/firstClearance.ts`) adds room only under the toolbar.
- **Host adapter**: the implementation of the ports for one host, the only code that calls that host's API (`src/host-vscode/` for VS Code).
- **Host API**: the host-neutral interfaces (ports) the core and the extension reach the host through: documents, files, settings, workspace, UI, Git, diagnostics, watchers, processes, assets and navigation (`src/host-api/`); no host API, DOM or Node imports.
- **Included block**: rendered block that comes from an `{include}`; maps to the directive lines and carries `data-sphinx-preview-included`.
- **Incoming-change mark**: green left bar on a block changed since HEAD (`data-sphinx-preview-changed`), from `src/page/modules/incomingChanges.ts`; ranges come from `src/core/mapping/lineDiff.ts` and `src/host-vscode/headBaseline.ts`.
- **Insert point**: "+" bar after each top-level block that opens an insertion editor (`.sphinx-preview-insert-point`).
- **Insertion editor**: block editor opened from an insert point or from "Start writing".
- **Link panel**: two-field Text/URL panel under the palette, opened by the Link button or Cmd/Ctrl+K (`src/page/modules/linkPanel.ts`).
- **List item editor**: block editor opened on one list item, on the lines the renderer gives the item, by a click on the item or Enter on the item selected with Right from its list (`editingElementFor` in `src/page/features/mappedBlocks.ts`); the list itself opens the whole list.
- **List item handle**: handle shown in edit mode left of each item of a list of two items or more (left of the outermost alert, quote or admonition that holds the list); a drag onto a sibling item or Alt+Up/Alt+Down on it moves the item with its sub-items among its siblings in one edit (`installListItemMove` in `src/page/features/listItemMove.ts`, `moveListItem` in `src/page/modules/listItemMove.ts`).
- **Mapped block**: rendered element carrying its source location (`[data-sphinx-source-file][data-sphinx-source-line]`).
- **Margin mode (planned)**: layout mode that uses the page margins for side content.
- **Message gate**: host rule that matches a page message to the preview before its handler runs (`render`, `comment`, `document`, `own-id`, `page-state`; `PAGE_MESSAGE_GATES` in `src/session/pageMessages.ts`).
- **Message registry**: map from a page-to-host message type to its validator (`PAGE_TO_HOST_VALIDATORS` in `src/core/protocol/pageToHost.ts`); the host handler is registered on the host's message router.
- **Message router**: typed `on(type, handler)` / `dispatch` table of one side of the protocol (`createMessageRouter` in `src/core/protocol/router.ts`), used by the host and by the page runtime.
- **Motion**: the short CSS effects of the preview (soft appearance, editor-closed fade, theme colour transition, update glow), driven by attributes from `src/page/modules/motion.ts` and turned off by `prefers-reduced-motion: reduce`; soft appearance needs `data-sphinx-preview-motion="on"`, set by the first pointer or key press and taken back by a content patch.
- **MyST autodetect**: check of used MyST syntax against `myst_enable_extensions` in the nearest `conf.py` (`src/core/myst/`).
- **Navigation history**: per-panel Back/Next stack of followed links (`src/core/state/navigationHistory.ts`).
- **Open-With editor**: the custom editor offered through "Open With" (`markdown-okf-schema-studio.editor`).
- **Orphaned thread**: comment thread whose quote can no longer be found; listed in the "Orphaned comments" box, never deleted (`src/page/modules/commentThreads.ts`).
- **Palette mode**: Strict / GFM / MyST button set of the edition palette, per workspace (`PALETTE_MODE_STORAGE_KEY` in `src/session/workspaceChoices.ts`, select in `src/page/modules/editPalette.ts`).
- **Preview panel**: the webview panel that shows the rendered preview.
- **Properties table**: rendered frontmatter table at the top of a document (`[data-okf-properties]`).
- **Protocol**: the typed messages between host and page, both directions, as discriminated unions with their validators (`src/core/protocol/`); no host API, DOM or Node imports.
- **Re-anchoring**: moving a thread's stored lines to follow its quoted text (`src/core/comments/anchoring.ts`).
- **Reading offset**: strip at the top of the viewport reserved for the sticky heading band (`refreshReadingOffset`, `docs/scroll-anchoring.md`).
- **Revision**: the protocol's name for one state of the document text (`revision` on the wire, `src/core/protocol/revision.ts`); compared for equality only. The VS Code host uses `TextDocument.version`; a host without versions counts with `RevisionCounter`.
- **Runtime**: the page script injected into the preview, bundled from `src/page/main.ts` into `out/bundle/preview.js`; it reads its boot context from an inert JSON element.
- **Runtime context**: the settings and ids the host passes to the runtime (`PreviewRuntimeContext`).
- **Scroll anchor**: the block and offset that keep the reading position stable across re-renders (`docs/scroll-anchoring.md`).
- **Shell**: the part of the preview page outside the content container; unchanged between renders of one document.
- **Shell key**: string identifying the shell, compared to decide whether a content patch is possible (`shellKey` in `src/core/preview/contentPatch.ts`).
- **Side channel**: host-to-page message carrying data that is not rendered HTML, for example `previewPropertiesTable`.
- **Sidecar file**: `<name>.comments.json` next to the document, holding its review comment threads.
- **Site header**: the header every page of the published site carries, written once by `siteHeader` in `test/site/siteHeader.ts`: the logo brand and the links Home, Contributing, How we ship, Gallery and Requirements; the requirements pages add the breadcrumb, History and Search.
- **Site tokens**: the cream colour tokens and font stacks of the published site (`SITE_TOKENS`, `SITE_CSS` in `test/site/siteTheme.ts`), each equal to a variable of the extension's cream preview theme; a test fails on drift.
- **Short ID**: `BLOCK-003`, a full ID without its tier and project prefix; the requirements viewer never uses it to name a requirement on a page (it is only the DOM id of a use case diagram), but its search accepts it.
- **Slash menu**: the `/` command menu of the block text boxes; it lists the palette's actions (`EditPalette.menuEntries`) and filters them as you type (`src/page/modules/slashMenu.ts`).
- **Social card**: the picture and the Open Graph and Twitter meta tags that a site page carries so that a shared link shows a large picture (`test/site/socialCard.ts`; pictures in `og/` of the site, 1200 x 630); the requirements viewer has one picture for its index (`requirements/og/areas-card.png`) and one per area (`requirements/og/area-<areaId>.png`), shared by the area's pages, and a share title that, on a use case or behaviour page, is the tab title without the site suffix: `Use case <full ID>: <title>` or `Behaviour <full ID>: <title>`).
- **Sticky heading band**: fixed band at the top of the preview showing the current heading path (`docs/scroll-anchoring.md`).
- **Marker block**: the requirement markers that sit together with no line of code between them. Several one-ID marker comments above one declaration or one test form one block, even when blank lines or prose comment lines (a JSDoc, an explanation) separate them; only a code line ends a block. A block names at most 3 distinct requirement IDs. To mark more, put each marker at the code or test it names: on another declaration, or inside the test body that checks it. Checked by `just check-markers`.
- **Table bar**: menu shown on a table in edit mode (`.sphinx-preview-table-menu`).
- **Table-cell editor**: block editor opened on one table cell ("Markdown table cell editor").
- **Text edit**: a replacement of the UTF-16 offsets `start` to `end` of a document text by `text` (`TextEdit` in `src/core/edits/textEdit.ts`); the pure planners of `src/core/edits/` return them and the document store applies them.
- **Theme mode**: preview colour scheme, one of `current`, `dark`, `white`, `cream` (`PreviewThemeMode` in `src/core/state/previewTheme.ts`).
- **TOC column**: runtime-created right column listing h1-h4 headings (`[data-sphinx-preview-toc]`), built by `src/page/modules/tocColumn.ts`.
- **Toolbar**: the controls bar at the top of the preview (`[data-sphinx-preview-toolbar]`).
- **Toolbar row**: `data-sphinx-preview-toolbar-row` `main` (Refresh, Edit, Export, collapse), `navigation` (Anchor, Theme, Back, Next), `view` (Width, Fold, Zoom out, Zoom in) or `review` (TOC, Side-by-side, Diff, Comments).
- **Top-level block**: mapped block that is a direct child of the content container (`topLevelMappedBlocks` in `src/page/features/mappedBlocks.ts`).
- **Update glow**: one brief wash of the focus colour on the blocks a content patch updated after a change made outside the preview and not in the active text editor, or an undo/redo (`data-sphinx-preview-updated`); the host sends `updatedRanges` (`src/core/preview/updatedRanges.ts`), the page marks them (`src/page/modules/motion.ts`).
- **View preference**: per-workspace preview setting changed from toolbar rows 2 to 4, `src/core/state/previewViewPreferences.ts`.
- **Warning banner**: one-line notice at the top of a successfully rendered page counting the `conf.py` MyST extension warnings, with Open Problems and close buttons; out of the flow, closed per document for the session (`[data-sphinx-preview-warning-banner]`, `src/page/modules/warningBanner.ts`).
- **Width mode**: Margin / Auto / Full width preview column state (`data-sphinx-preview-width`); Auto lets wide tables and figures break out of the column.
- **Detached save**: a final save whose editor the writer closed with Cancel or Escape while it was in flight; the host answers it with `done` or an error that gives the typed text back (`src/page/features/detachedSave.ts`, `src/session/features/detachedEdits.ts`).
- **Edit in flight**: an open editor, or a detached save the host has not answered; no other edit gesture starts meanwhile.
- **Line hand-off**: the 1-based line a Studio tab reveals and marks when it opens or is revealed from a command, a link, Back or Next; held once as a pending line for a new Studio tab (5 seconds, `PendingLines` in `src/core/navigation/pendingLine.ts`), or given to a live Studio tab (`src/host-vscode/studioTabs.ts`).
