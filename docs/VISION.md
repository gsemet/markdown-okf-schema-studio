# Vision

**Markdown OKF-Schema Studio: read, annotate and edit rich Markdown documents.
A beautiful, rich and collaborative surface between you and your coding agents, in VS Code.**

## Who it is for

- **Developers working with coding agents.** They review Markdown all day long (plans, analyses,
  specifications, reports) and get plain, tiring renderings.
- **Writers who use MyST.** They want to see and edit cards, grids, admonitions, tabs and figures
  as they will be published, without running a Sphinx build.

## Why this extension

### We read less code and more Markdown

Coding agents now write most of the code. What we read, review and decide on is increasingly
Markdown. The document has become the place where a person and an agent agree on what to build.

Agents are naturally good at Markdown, and not only the basic kind. Models already know how to
write [MyST](https://mystmd.org/) directives, Mermaid and PlantUML diagrams, Vega-Lite charts and
large tables. MyST is underrated: it gives a Markdown document the structure of a real page, and
it stays plain text.

### The usual tools fall short

- **VS Code Markdown extensions** are plain-looking, reformat your text when you edit it, or miss
  the one capability you need: MyST, diagrams, charts, tables, comments.
- **Obsidian** renders and edits Markdown nicely, but it works through a vault, and most
  capabilities need a plugin.
- **An HTML report generated by the agent** looks great, but it is a dead end: you cannot
  annotate it without a hand-saved JSON file or a backend, and it is heavy for the agent to write
  and to rewrite.
- **Agentic planning tools** such as [GitHub Next's Chopin](https://github.com/githubnext/chopin),
  an MIT-licensed research prototype, run as a service: a server, a database, a GitHub App and a
  model key, with their own syntax for talking to the agent. We wanted the same collaboration on
  plain local files, in the editor we already use.

## The loop it enables

1. The agent writes a plan in Markdown. It knows it can use advanced syntax (cards, admonitions,
   a diagram, a chart, a wide table) where it helps, without overloading the page, instead of
   generating a complex and non-interactive HTML page.
2. You read it in the Studio, rendered as a real page, at a comfortable width.
3. You annotate it: a `TODO` note or an HTML comment in the text, a review thread on a sentence,
   or a direct fix in a block.
4. You ask the agent to react. It re-reads the file and the review comments file, answers, edits
   and resolves. The diff only shows what changed.

## What the Studio is

A WYSIWYG companion for one Markdown page at a time, inside VS Code, built on local files:

- **Rich reading.** GitHub Flavored Markdown and MyST render faithfully: cards, grids,
  admonitions, tabs, figures, maths, Mermaid and PlantUML diagrams, Vega-Lite charts, tables. The
  text column has a comfortable reading width, and wide content gets the room it needs.
- **Annotation for people and agents.** `TODO` notes and HTML comments live in the Markdown
  itself, so an agent re-reading the file sees them. Review threads are saved in a JSON file next
  to the document, so they can later be shared with teammates or handled by an agent.
- **Editing where you read, in small raw blocks.** Clicking a block opens its exact Markdown
  source. Only that block changes when you save: no reformatting, a clean diff. The palette and
  the `/` slash menu insert any construct.
- **Readable front matter.** [OKF](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)
  (Open Knowledge Format) bundles are folders of Markdown files with YAML front matter. OKF
  requires only a `type` key and accepts any other key.
  [OKF-Schema](https://github.com/gsemet/okf-schema) adds a JSON Schema per document type, for two
  purposes: limit what a field may hold, and document the fields for agents. The Studio shows the
  front matter as a properties table and reports schema problems on the field concerned.

## What it is not

- Not a service: no account, no server, no external dependency to set up.
- Not a documentation build: it does not replace Sphinx or MyST builds, and constructs that need a
  build show as labelled placeholders.
- Not a document database or a vault: it works on the files of your repository, one page at a
  time.
- Not a heavy toolchain: OKF-Schema is a simple linter that asks the agent to fix the syntax.
  Agents handle Markdown with front matter perfectly, because it is their natural language.

## Principles

1. The Markdown file is the source of truth. The Studio never rewrites what you did not touch.
2. What an agent can write, the Studio can render.
3. Reading comes first: comfortable width, calm typography, no surprise layout shifts.
4. Annotations are plain data that agents and people can both read.
5. Today it is a VS Code extension. The rendering engine is kept apart from the VS Code host, so
   other integrations, such as a standalone application, remain possible if users ask for them.
